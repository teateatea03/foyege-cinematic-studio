# 專案封存、素材用途與協作改稿

在多人／多代理改同一製作、準備移機／封存，或要整理第三方素材的使用與署名時按需閱讀。一般提示詞不要求建立整套管理表。此頁是製作支援，沿用既有 [素材與成片交接](media-handoff.md)，不改導演核心。來源見 [T30–T33](tutorials.md#2026-11-09-專案維護研究)。

## 封存要能重開

保存高品質原始版本及描述資訊；母版、實際使用的原素材、主音軌、字幕、工程／時間線、參考映射與已接受 take 清單各有版本。另記使用軟體／插件、模型／工作流版本、字型／LUT 等外部依賴的位置和可取得條件。不要因已有影片或工程檔，就假定全部依賴已包含。[T30](tutorials.md#t30-數位影片保存)

需要重現生成時，保存實際 workflow、輸入版本／雜湊、參數及工具／模型版本；seed 一樣不保證跨版本逐位元組一致。大型權重、可重建快取及正式素材分清必要性，不為了封存自動下載或複製全部資源。只有母版而缺工程時，交付「可播放」與「可重新編輯」的能力分開。

為需要保存的檔案建立 manifest：相對路徑、位元組數、SHA-256、版本及用途。先對確定的良好版本建立基線；轉碼、修訂或格式遷移另產版本與新校驗值，保留舊基線與轉換紀錄。對一份已損壞的檔案重新算 hash，不會使它變成良好版本。[T31](tutorials.md#t31-校驗與完整性)

獨立副本記錄媒體／位置及已檢查範圍。同步、同一裝置上的另一個資料夾、單一 NAS 的多個路徑或 Git 遠端，不因名稱不同就算已具獨立故障保護；Git 有提交也不代表權重、忽略檔或外部媒體一併存在。按實際依賴查缺口，不自動移除候選、舊版本、日誌或備份。

### 恢復到新位置驗證

需要驗證恢復時，先選有代表性的工程／素材／音軌／字幕小組合，將所選副本恢復到新的暫存目錄，核對 manifest，再於對應軟體檢查重新連結、字型／LUT、開頭與結尾及已知高風險區間。檢查不應悄悄從原始路徑讀到缺少的依賴；必要時用相對路徑或記錄實際解析位置驗證。完整開啟／播放範圍未做時明確保留未檢查。

hash 不符時先保留異常檔、基線與日誌，核對是否是有紀錄的修訂，再與已知良好副本比較。不直接以新 hash 覆寫基線，也不在未定位版本前覆蓋唯一原檔。恢復成功附副本來源、驗證時間、檔案與應用層覆蓋；小組合成功不等於整個專案、NAS 或備份制度皆已驗證。

## 素材用途與署名紀錄

沿用素材 ID，只有用到第三方素材或需要交付權利資訊時補下列欄位，不為普通草案新增行政門檻：

| 欄位 | 要保留的依據 |
| --- | --- |
| 來源／版本 | 原始網址或提供者、取得日期、素材版本／雜湊 |
| 使用角色 | 只作研究參考、生成控制輸入、嵌入成片、配樂、字型／LUT、公開附件等實際用途 |
| 適用依據 | 自有／使用者提供的授權／實際授權條款與版本／待確認，及證據位置 |
| 條件與交付 | 實際允許範圍、需要保留的署名／修改說明、依據的確認狀態 |

CC 素材依實際授權版本整理 Title、Author、Source、License（TASL）；有標題才列，依提供的作者／署名要求處理。CC0 與 Public Domain Mark 不套成所有 CC 授權的相同署名義務。這張紀錄表本身不授予使用權，公開可觀看或已有來源連結也不等於可將原作納入成片。[T32](tutorials.md#t32-素材來源與署名)

把「技術上可讀取」與「可用於這次指定用途」分開。用途尚待確認時仍可完成自有素材草案、鏡頭設計與替代清單；需納入交付的素材則逐項核對依據，不因記錄未知就阻塞無關工作。私人授權文件與個人資料保留在指定私人位置；公開交付只帶必要署名與摘要，不把合同或憑證放入公共 repo。

## 協作：清楚的寫入範圍與基線

多人、Codex／Claude 或不同工具協作時，先列「負責的工程／場次／檔案、起始版本、可讀／可寫範圍、交回版本與整合責任」。依編輯器的實際鎖定機制或不同工作副本避免同時覆寫同一工程。Adobe Productions 的 project locking 是一個具體例，不代表所有 Blender、剪輯工程或同步資料夾都有同樣保護；工具鎖也不是作業系統 ACL／帳號權限。[T33](tutorials.md#t33-共享專案與寫入責任)

不因檔案看起來閒置而刪除他人的鎖或覆寫工作；先查當前編輯者與工具狀態，再依實際支援流程交接。純文字／程式可用既有 Git 分支及 diff 整合；二進位工程依既有工具的鎖定或分工方案，沒有自動合併能力就不假裝已無衝突。此頁不自行擴大帳號權限、建立新服務或派發代理。

改稿記錄採最少資訊即可：

```text
問題／需求 ID、對應的時間線或審片版本及時間區間：
希望觀眾看到／聽到的改變：
受影響的 shot／take、工程、音軌／字幕及依賴：
負責範圍／起始版本：
回交版本／實際改動及未改項：
整合結果：待整合／已整合待驗／已接受＋證據
```

把意見、執行和接受分開；「修好了」不是已接受成片。改稿之間先找互相矛盾或共用依賴的要求，再決定整合順序，保留不受影響的已接受素材。交回時比對目前基線，不能用較舊工程覆蓋別人的新改動。時間線改剪後，舊審片的時間碼需重新對應。

最小封存／交接可只是一份對照清單與現有檔案；按實際製作規模展開。收集方法與檢查工具不等於已完成真實專案恢復或授權審核，實際結果各自記錄。
