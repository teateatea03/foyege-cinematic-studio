# 素材、剪輯交接與成片驗收

在收素材、剪輯交接、混音、字幕或交付成片時按需使用；純劇本與單鏡提示詞不展開整套清單。這份參考補強製作周邊，不改人物目的、微表演與分鏡核心。來源與版本見 [T24–T29](tutorials.md#2026-11-09-製作周邊研究)。

## 素材進場與代理對應

保留原始媒體、已接受生成 take、主音軌及其版本，工作副本／代理另存。從 NAS 或相機複製時核對來源、位元組數與雜湊；複本核對成功仍不等於已驗證原檔內容或已有獨立備份。名稱只是定位，不靠「final」字樣判定接受狀態。

| 用到的欄位 | 交接內容 |
| --- | --- |
| 素材身份 | asset／shot／take ID、角色／場景版本、來源與本機／相對媒體位置、版本／雜湊 |
| 媒體規格 | 視音軌、尺寸、畫幅／像素比例、實際時間範圍、fps 與時間基準、音訊取樣率及聲道 |
| 色彩與衍生 | 已知色彩標記、已套用處理；代理／轉碼檔指回哪份原檔 |
| 狀態 | 計畫、未審、已接受、需修正；證據與負責版本 |

原檔、剪輯代理與生成用控制影片責任不同：代理讓剪輯更流暢，不自動成為新的身份／表演基準。使用既有剪輯器建立代理時，核對它要求的時長、fps／時間戳、聲道及重新連結條件，先以小段驗證。最終交付前確認連回正確高品質來源，沒有意外使用低清代理或舊 take。[T24](tutorials.md#t24-素材匯入與剪輯代理)

可用既有 ffprobe 取得基本資訊；在新的證據目錄執行，輸入與輸出換成實際路徑，並檢查程序退出碼為 0 後才採用輸出：

```powershell
ffprobe -v error -show_format -show_streams -of json "input.mp4" | Out-File -Encoding utf8 "probe.json"
```

容器 duration、avg_frame_rate 或 r_frame_rate 不是完整時間映射。懷疑 VFR、裁切或同步漂移時再取相關區間的幀時間戳；不要為了交接把所有素材一律改成 60fps。轉碼、重採樣、補幀與慢放各自記錄，時間碼同時綁定片段起點與來源版本。

## 交接的是時間線，不只一個專案檔

交接時按實際需求提供媒體清單、時間線版本／fps／起點、可用原始區間、音軌／字幕版本，以及帶 shot／take ID 和時間碼的審片檔。審片燒字版與乾淨母版分開，避免把工作標記當成片字幕。

跨軟體的 XML、AAF、EDL 或 OTIO 依實際剪輯器／adapter 能力選用，不假定完整保留調色、轉場、巢狀時間線、音訊路由、特效與變速。先用代表性片段往返測試，對照審片檔的切點、長度、字幕及聲音。不能傳遞的效果附設定或經確認的烘焙片，並保留未烘焙原始版本。[T25](tutorials.md#t25-時間線交換的能力邊界)

一次改稿記錄受影響 shot／take、音軌／字幕、原／新區間與原因。替換單鏡不覆蓋無關已接受素材；變速或改剪之後重查音樂、對白、字幕與後段同步。實際素材映射沿用 [事件對照](performance-transfer.md#對齊事件再比較各層)。

## 聲音：主檔、測量與聽審分開

MV 的鎖定歌曲、對白、環境／效果與模型附帶聲音分清來源及用途；有 stems 才記分軌，沒有就不假造。保留主檔，混音和平台版本另存，不因校準響度改寫已鎖定演唱、時間或原始音檔。

記錄交付目的、聲道配置、取樣率、實際 integrated loudness、true peak、處理歷史與採用規格。EBU R 128-2023 的 −23 LUFS 與線性製作端 −1 dBTP 是廣播建議脈絡，不是所有網路 MV 的預設。沒有交付規格時先記量測值，不自動套 −14 LUFS 或壓限。少於一分鐘的節目，不把 LRA 當穩健品質結論；原規範也提醒資料點不足。[T26](tutorials.md#t26-響度與真峰值)

以下用已有 ebur128 濾鏡讀取一條音軌，不改動輸入：

```powershell
ffmpeg -hide_banner -nostdin -i "mix.wav" -map 0:a:0 -af "ebur128=peak=true" -f null -
```

量測全片／抽樣範圍要寫清，完成最終編碼後再檢查交付檔，不能用混音前數值代表編碼後真峰值。先確認聲道內容，避免把雙單聲道誤當立體聲，或把立體聲直接當成已通過單聲道相容性。

自動量測與可解碼只驗結構。對白／旁白逐段以本機 ASR 對稿或明確人類回聽確認；可懂度、情緒演法、爆音、接縫、相位及聲畫同步按實際聽審記錄，ASR 不能代替所有聽感驗收。未聽就保留未檢查。產生或補齊 PCM 時先算整數 sample frames，核對聲道、樣本寬度及 data 區塊符合 block align，不能按小數秒任意拼 bytes。

## 繁中字幕與歌詞

先指定字幕用途：翻譯字幕、同語字幕／SDH、歌詞或逐字變色。文字綁音軌與剪輯版本，保留核准用字、專名及日文假名；自動轉寫作初稿，逐句核對否定詞、數字、說話者及實際音訊。SDH 依理解需要補聲源／非語言聲音，不把視覺動作隨意寫成聲音事實。[T27](tutorials.md#t27-繁中字幕的交付脈絡) [T28](tutorials.md#t28-字幕準確性與可及性)

Netflix 繁中一般字幕的 16 字／行、成人 9 字／秒只是該交付規範的具體例；SDH、兒童及其他平台規格不同。一般創作先依實際媒介與閱讀速度設計，不宣稱符合 Netflix，MV 也不套它的主題曲字幕取捨來刪歌詞。

按語意和畫面分句，確認入出點、間隔、閱讀負荷與說話者。逐字歌詞另綁音節／音樂時間，不能只拿一條句級字幕假稱完成逐字同步。沒有音軌時標暫定，未確認的字與時間保留待校。

在目標畫幅和播放器檢查繁中、日文、符號的字型字形、換行、對比、遮擋和裁切；燒錄字幕與外掛字幕各自驗。SRT／VTT／ASS 的樣式與相容性按工具實測，不能因檔案可解析就假定播放器顯示相同。

## 母版、平台版與驗收

先綁交付 profile：用途／接收者、尺寸與畫幅、fps／時間基準、編解碼及位元率／品質、色彩、聲道與音訊規格、字幕方式、版本和檔名。母版、審片版、上傳版分開；沒有指定平台時不自動把一套規格套到全部用途。

YouTube 官方上傳頁可作該平台候選：例如 MP4／H.264、48kHz 音訊、保留內容既定幀率及 SDR BT.709；仍按最終母版、HDR／SDR 和實際上傳要求選用，不把未知來源直接改標 BT.709、硬拉 16:9 或補成 60fps。[T29](tutorials.md#t29-youtube-上傳規格)

| 層 | 最少要確認的事 |
| --- | --- |
| 檔案／結構 | 來源版本、檔案存在與雜湊、可解碼、視音軌／時長／畫幅及實際編碼符合 profile |
| 內容 | 沒有錯 take、代理、意外黑格／凍格／缺格、尾音裁斷、舊字幕／水印；有意黑場和定格依設計判斷 |
| 同步／播放 | 原速看片及聽審頭、中、尾與已知高風險切點；字幕、聲音、變速與長片末端漂移各自記錄 |
| 交付／封存 | 乾淨母版、實際平台版、字幕、混音／既有分軌、時間線與媒體映射、規格及檢查結果 |

檢查採通過／需修正／未檢查，附版本與時間點。只看抽樣就記抽樣範圍；完整播放另記覆蓋。串流平台轉碼後可用時另查播放、色彩、字幕與聲音，但不由本頁取得發布或上傳授權。

最小交接單可縮成一行：「交付版本 → 使用素材／音軌／字幕版本 → profile → 實際檢查與範圍 → 待修／未檢查」。規格不明時先完成可逆整理，不擅自重新混音、轉碼或清除原始資產。
