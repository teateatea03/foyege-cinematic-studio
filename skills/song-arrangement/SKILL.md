# 歌曲編曲與情緒起伏

把一首歌從「每段都差不多」改成「聽得出走到哪裡」。這份技能處理寫譜和編曲。聽感由人判斷，數字只用來找問題。

來源與採用程度見 [來源](references/sources.md)。實際失敗案例見 [F01 案例](references/f01-case.md)。提示詞比譜優先的案例見 [F04 案例](references/f04-case.md)，好的一首能不能重現見 [F05 案例](references/f05-case.md)。

## 先確認

- **要保留什麼：** 對方已經喜歡的段落、律動或聲音，每輪都拿來比。
- **被批評什麼：** 記下原話，不要先翻譯成技術詞。
- **參考曲：** 對方拿來比的那首。沒有參考曲時，問一首就好。
- **先調提示詞：** Owner 聽完 F04 說「提示詞的重要性 非常非常的優先」。動譜或後製之前，先比較不同提示詞，至少換幾個種子再下結論。寫明速度；只描述這段有的內容；指定樂器分工，讓人聲有空間。F05 拆開比較：加上分工，主歌其他樂器的進出幅度比只刪減更穩定變高（是否更乾淨仍由聽感確認），但兩者都讓副歌加的樂器變少，所以副歌加入什麼要另外寫明。好的一首不是配方，同一段文字換種子不會重現，要多抽幾次再挑。
- **工具能控制什麼：** 先查再寫，不要假設。例如 YuE2 的譜只控制人聲旋律、一條樂器旋律、和弦和整首一個速度；style 是全曲一段文字。

## 流程

### 1. 先寫情緒地圖，再寫音符

每段填一行。這張表沒寫出來之前不寫譜。

| 段落 | 能量 1–5 | 這段的工作 | 故事事件 | 和上一段不同的兩件事 | 和上一次出現不同的地方 |
|---|---|---|---|---|---|

- 相鄰兩段至少有兩項不同：音域、節奏密度、和聲、人聲編排、配器密度、空間。
- 先做出低點。基準不夠低，後面就沒有高點可去。
- 主歌收、前副歌推、副歌放、橋段落下、最後副歌比第一次多一件新東西。
- 副歌變大，常常是因為前一段變小。加東西之前先試著拿掉東西。

### 2. 把歌詞的轉折變成音樂事件

歌詞裡的玩笑、反轉和真心話，要有對應的音樂動作，否則情緒只停在文字裡。

- 反轉或吐槽前：全部停一拍，再一起打回來。
- 系統出錯、慌張：切碎的節奏、斷奏、突然換和弦。
- 真心話：抽掉鼓和低頻，只留一兩樣樂器，聲音靠近。
- 最重要的一句：留白，讓那句前後都有空間。
- 結尾的笑點：突然停，不要淡出。

### 3. 旋律

- 副歌通常比主歌高，音符更長、節奏更簡單；主歌短促、節奏多。
- 前副歌往上爬，歌詞更直接，和聲不要解決。
- 一個短動機可以重複，但要用律動、和聲或配器讓它每次不同。
- **同音連打要有限度。** 快嘴段可以多一些，但不能整首都是。寫完用 `scripts/score_stats.py` 量。這個數字不能單獨判好壞：Owner 點名「完全不同」的 P103 同音比例是 71%，是快速半說半唱（見 [`suno-reference-prompts`](references/suno-reference-prompts.md)）。
- **不要為了字清楚犧牲旋律。** 同音最容易被機器聽懂，也最平。ASR 只用來找錯字，也不要拿來排名選曲。F03 用「照譜加 ASR」排名，排不出律動和風格。
- 句尾、長音和高點要落在有意義的字上。
- **句尾要留空。** 排滿的小節接下一句第一拍，聽起來很急，下一句的字頭也會被吞掉（見 [`f03-case`](references/f03-case.md)）。
- 主歌要唱還是半說半唱，先對照 Owner 的提示詞再決定，不要自己改方向。
- 先查歌手的低音清不清楚。YuE2 主歌碰到 D4 以下的句子，字常常糊掉（線索，見 [`f03-case`](references/f03-case.md)）。

### 4. 和聲

- 不同段落用不同進行。全曲同一組和弦循環，起伏會明顯變少。
- 主歌可以少變化或低音持續；前副歌用懸著、不解決的和弦；副歌用簡單有力的進行，主和弦的份量更重。
- 小調裡，強屬和弦（Fm 調的 C 或 C7）比小屬和弦（Cm）更有往回拉的力量。
- 最後副歌可以先在落下的段落降下來，再往上轉調，對比會更大。
- 用工具支援的和弦種類，不要只用三和弦。YuE2 方言與公開腳本邊界見 [工具說明](references/tools.md)；完整和弦／生成支援要核對所用 YuE2 執行環境。

### 5. 配器層次

用五種元素填每一段，同時響的通常 3 個夠用，4 個是上限，5 個很少成立。節奏完全相同的樂器算一個。

| 元素 | 工作 |
|---|---|
| 基礎 Foundation | 鼓和貝斯 |
| 鋪底 Pad | 長音、和弦 |
| 律動 Rhythm | 和基礎相對的動態，例如琶音、切分、搖鈴 |
| 主角 Lead | 人聲或主奏 |
| 填空 Fill | 句子空隙裡回答主角的短句 |

- 每段先決定誰最搶耳，其他部分降低活動量。
- 人聲在前，層次在後。層次太突出聽起來只會亂。
- 重複的段落要有變化：多一層和聲、一句回應、一個新音色。
- 各樂器要有自己的頻段和空間，不要全部擠在低中頻。

### 6. 轉場

- 進副歌前拿掉低頻或鼓，或留一拍空白。
- 用上升音效、濾波打開、鼓點變密來推，不必改速度。
- 換段的第一拍要讓人聽得出換了。
- 一次只加一到兩樣，一下全部加進來會變成突兀的跳動。

### 7. 製作和混音也要有對比

下列數字是作者案例，不是規則。

- 副歌比主歌大約 1–5 dB。
- 主歌人聲較窄、較乾；副歌雙軌或三軌、較寬、殘響較大。
- 主歌收高頻，副歌打開。
- 編曲時就考慮頻段衝突和 sidechain，不要全留到混音。
- 殘響要有預延遲，並在人聲響時壓低，否則前一個音會和下一個音疊成兩個音高。
- 最後響度用固定增益。`loudnorm` 可能自動改成動態模式，把段落對比壓掉。

### 8. AI 流程的分工

單一模型一次生成整首時，很難逐段控制編曲。可以這樣分工：

1. **模型唱歌：** 用模型生成人聲和基本律動。
2. **AI 做真分軌：** 各元素各自生成或由 MIDI 演奏，逐段進出。
3. **AI 組裝成品：** 每個計畫都要交出 AI 做好的混音和分軌。對方不需要做混音。

先用一段短窗測試，例如主歌到第一次副歌，通過再做全曲。**短段成立不代表全曲成立**：30 秒聽起來刺激的念唱，4 分鐘可能很單調。

### 9. 用機器找問題

以下從本技能目錄執行，依賴與輸入格式見 [工具說明](references/tools.md)。

```bash
python scripts/score_stats.py 我的譜=score.abc
python scripts/arc_compare.py 我的版本=stems_dir:take_id 參考曲=ref_dir:ref_id
```

先比參考曲，不要設絕對門檻。數字指出可能的問題，不代表好聽。下表的原因是常見方向，要逐項驗證。

比段落前，先用歌詞找到參考曲真正的段落位置。混音前，先比各分軌相對人聲的音量。疊 AI 樂器前，先量每層的延遲。段落對比要量最後的檔案。理由和數字見 [`references/f03-case.md`](references/f03-case.md)。轉調、逐句讀字、換句，以及從原 take 接著唱的做法見 [`references/f06-f07-case.md`](references/f06-f07-case.md)。

| 聽到 | 先量 | 常見原因 |
|---|---|---|
| 平、沒有起伏 | 同音比例、各段和弦、段落音量和亮度範圍 | 每段工作相同；沒有低點 |
| 像念字 | 同音比例、音程、長短音 | 旋律太少移動 |
| 伴奏感、電子琴感 | 鼓和其他樂器佔比、2–14 kHz、立體聲寬度、循環比例、其他樂器的頻譜平坦度 | 只有單一和聲層跟著鼓走；頻段擠在低中頻；音色太乾淨 |
| 很亂 | 同時響的元素數、人聲佔比 | 層次太多或太前面 |
| 破音、忽大忽小 | 真峰值、滿刻度樣本、1 秒音量跳動；也查播放器 | 不一定在檔案裡 |
| 音不準 | 畫音高曲線對譜；懷疑八度時換第二種方法並看頻譜 | 滑音或倍週期讓數字誇大；真的偏的通常很少，不要整首校正 |
| 只有整首才分岔、發糊，單軌沒有 | 逐軌比那一刻：殘響對人聲的比例、其他軌的音高 | 殘響留住前一個音 |
| 字聽不清 | 每句 ASR 跨 take 比較、該句最低音 | 音域太低；同譜可從別的 take 換句，但要先確認是同一個歌手 |
| 句子接太急、下一句字頭不見 | 譜上句尾長度和休止；頻譜上有沒有子音 | 句尾排滿沒留空；先換子音清楚的 take，再改譜 |
| 換句後聽起來不同人、腔調變了 | 用說話人模型比換進去的片段和前後 8 秒，以原版自己同一處為基準；頻譜（LTAS、MFCC）抓不到 | 同譜同模型的不同種子可能是不同歌手，按段比像，按句換進去不一定像；腔調機器量不到，由人耳判斷 |
| 換句的接縫聽得出來 | 接縫兩側和原版比：唱的時間差、人聲對伴奏的比例、音色跳動，以原版自己同一處為基準 | 換進來的歌手唱得較早或較晚；整段換進來時混音比例不同。能多抽就多抽，拼接只補小地方。YuE2 可以從原 take 存下的 semantic token 接著唱，F08 的 14 首機器都量不到接縫（見 F08 案例） |
| 要求的轉調沒出現 | 譜裡有沒有 `K:` 欄位；伴奏色度的調；人聲中位數和譜面的差 | 只寫在文字裡；寫進 YuE2 的譜才會轉 |
| ASR 讀字很差，但人聽得懂 | 歌詞有沒有假名人名、La、Hey；切音檔的位置是不是實際唱的位置 | ASR 寫不出假名；譜上的段落標記不等於實際唱的位置，要用附時間的 ASR |

## 不要做

- 不用「更有情緒」「更專業」這類話交差，要寫成聽得出差異的動作。
- 不把社群配方或模型提示詞當成保證，先做對照。
- 不把單一種子的聲音當成提示詞的效果。P103 換了種子就沒有回來。
- 不一次改很多又無法比較。可以同批跑多個版本，但每個版本只改一個方向。
- 不因數字接近參考曲就說通過，最後由人聽。
- 不模仿特定歌手或歌曲的聲音，也不把受版權保護的參考音訊放進生成流程。

## 完成時交付

- 情緒地圖和故事事件表
- 譜或各分軌的進出表，以及 AI 做好的成品混音
- 和參考曲的數字對比，並說明哪些數字可能失真
- 明確區分機器結果、人聽判斷和還沒驗證的事

## GPU 資源規則

支援 GPU 的製作工作使用 GPU，只有軟體不支援時才用 CPU；GPU 忙碌不是 CPU 回退理由。依使用者選定且已授權的單張 GPU 排程，記錄裝置與後端；同卡重工作序列化，不自行啟停其他工作，也不因忙碌或 OOM 改成 CPU／另一張卡。只有軟體不支援 GPU 的步驟才用 CPU，並記原因。
