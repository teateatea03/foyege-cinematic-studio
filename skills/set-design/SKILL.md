# 場景設計

公開版保留本機室內場景研究的方法與腳本。Owner 指專案決策者，接受點依實際專案設定；既有授權可沿用。

這份技能負責把一個場景從需求做到可以拍：平面圖、3D 白模、自動檢查、參考畫面，再交給定場照和預演。拍片的整體順序看 `film-production`。

## 原則

1. **一個模型當母本。** 平面圖、立面圖和每個機位的畫面，都從同一份 `set.json` 和它建出的白模產生。要改佈置就改 `set.json`，再重出全部的圖，不要在單張圖上改。
2. **先想人怎麼用這個房間。** 誰在這裡、每天做什麼、從門口走到哪裡、坐在哪裡工作。家具照真實尺寸擺，前方要留出使用的空間，例如椅子拉出來、衣櫃門打開。
3. **用公尺和真實尺寸。** AI 生圖常把房間畫錯比例，白模不會。常用尺寸看 [space-planning.md](references/space-planning.md)。
4. **為鏡頭設計。** 主要機位畫在平面圖上。房間裡放不下的機位可以拆掉一面牆（wild wall），但要寫進 `set.json`，生成時那面牆不能出現。
5. **白模管位置、光與已定材質方向。** 代理色只用已確認的真實材質色；未定的一律中性灰。不能為辨識物件輪流塗不同顏色，生成模型會照抄。細緻材質和風格由定場照補足。
6. **機器先查，Owner 看圖。** 重疊、走道、開門、擋窗、機位被擋這些腳本查得到的，先自己修好。Owner 只判斷機器判斷不了的，例如像不像這個人的房間。一次只問一件事。
7. **版本化。** 每個場景有 SET ID 和版本號。改了就升版，並列出受影響的鏡頭。

## 流程

| # | 步驟 | 交付 | 過關條件 |
|---|---|---|---|
| 1 | 需求 | 這個場景出現在哪幾場、發生哪些動作、哪些時段、哪些道具和狀態變化、需要哪些機位；人物的生活習慣推出家具清單 | 拆解表裡這個場景的每一列都對到需求 |
| 2 | 平面圖 | `set.json`，加 `plan_check.py` 出的 `plan.png`、`plan_cameras.png` 和報告 | 沒有 FAIL；每個 WARN 都寫了保留的理由 |
| 3 | 白模 | `build_set.py` 出的 `scene.blend`、俯視圖、四面立面圖、每個機位各時段的畫面 | 沒有 FAIL；每個 `must_see` 都看得到 |
| 4 | 自查 | 對照劇本逐場看：動作做得到嗎、光從對的方向來嗎、機位拍得到該拍的嗎 | 每場都寫了結論 |
| 5 | Owner 審 | 平面圖加各機位白模畫面，拼成一張 | Owner 接受 |
| 6 | 定場照 | 用白模機位畫面當構圖，生成同角度各時段的定場照 | 和白模疊圖，門、窗、大型家具的位置對得上 |
| 7 | 預演 | 人物替身放進同一個房間，排走位和鏡頭 | 視線、左右和接觸對象都對 |
| 8 | 交付 | 寫進專案的 `DESIGN_SETS`：SET ID、版本、檔案和 SHA-256、道具表、各時段的光、可用機位 | 後面的鏡頭卡都能引用 |

**第 1 步：** 從 `film-production` 的拆解表開始。光的需求要寫成「哪個時段、光從哪扇窗或哪盞燈來、什麼色溫」，第 3 步才能做出來。道具要寫狀態怎麼變，例如毯子從椅背移到主人身上。

**第 2 步：** 複製 [sample_room.json](assets/sample_room.json) 來改。格式、座標和每項檢查的意思見 [set-json.md](references/set-json.md)。先擺大型家具（床、書桌、衣櫃），再擺配合的家具（椅子、床頭櫃），最後擺放在家具上的東西、燈和機位。劇本裡人物常待的位置，放一個和角色同身高的替身（`actors`）。

**第 3 步：** 建模、檢查和出圖的細節見 [blender-blockout.md](references/blender-blockout.md)。定場用的廣角機位加 `"level": true`，牆的垂直線才不會歪。

有太陽的室內場景先看輸出的 `sunlight.json`：從牆外沿入射方向穿過完整牆厚，查每扇窗的室內面四角；窗楣／窗框先擋住時記遮擋，不虛構室內落點。通過後列第一個落點、物件表面與世界座標，確認後再寫光斑描述。太陽在窗背面時記「不入窗」，不能照生成圖倒推物理。四角不等於完整照度或所有遮擋已驗，指定家具／替身可另做朝陽面取樣，方法與限制見白模參考。

無牆虛擬空間、斜向道具或發光介面可用專案自己的 Blender 驅動與場景 JSON；保留同一母本、機位、輸入雜湊及 GPU 規則，不假稱室內矩形房間檢查已覆蓋這些模型。

**第 6、7 步：** 白模交給 AI 的方法、預演的指令和已知風險見 [ai-handoff.md](references/ai-handoff.md)。生成要先有 Owner 批准的工單。上傳參考圖之前，先查專案對哪些圖可以上傳的規定。

## 工具

從本技能目錄執行，先確認 Python、Pillow 和 Blender 的入口：

```bash
python scripts/plan_check.py --set SET.json --out OUT_PLAN
```

```bash
blender --background --factory-startup --python-exit-code 1 --python scripts/build_set.py -- --set SET.json --out OUT_BUILD --gpu-name "YOUR_GPU_NAME"
```

```bash
python scripts/overlay_check.py --blockout OUT_BUILD/cam_C1_day.png --image STILL.png --out OUT_OVERLAY
```

- `plan_check.py`：只要 Python 和 Pillow，不用 Blender。檢查平面上的問題，畫出平面圖。有 FAIL 時結束碼是 1。
- `build_set.py`：Blender 5.2，Cycles 優先單張 GPU，NVIDIA 優先 OptiX，必要時試 CUDA；以實際裝置名稱指定 `--gpu-name "YOUR_GPU_NAME"`。軟體無任何支援的 GPU 後端時才可用 CPU，manifest 必須記錄原因；指定顯卡找不到、顯卡忙碌、記憶體不足或渲染錯誤均不得自動退 CPU。加 `--no-render` 只做建模和幾何檢查，不啟動 GPU 渲染。
- `overlay_check.py`：把生成的定場照和白模畫面疊在一起，比較輪廓。
- `to_previs.py`：把一個機位轉成 foyege 預演腳本的輸入，預演就在同一個房間裡排走位。
- 輸出資料夾必須還不存在，舊結果不會被蓋掉。每次輸出都附 `manifest.json`，記錄輸入的 SHA-256、檢查結果和每張圖的渲染秒數。

## 專案檔案

支援 GPU 的製作工作使用 GPU，只有軟體不支援時才用 CPU；GPU 忙碌不是 CPU 回退理由。依使用者選定且已授權的單張 GPU 排程，記錄裝置與後端；同卡重工作序列化，不自行啟停其他工作，也不因忙碌或 OOM 改成 CPU／另一張卡。只有軟體不支援 GPU 的步驟才用 CPU，並記原因。平面圖、JSON、碰撞／射線檢查及一般檔案工作目前是 CPU 程式，不為這些另建 GPU 實作。圖片生成優先沿用專案既有且可用的本機工具；只有使用者選定外部服務且已有授權時才送出。

| 檔案 | 放哪裡 |
|---|---|
| `DESIGN_SETS`（場景設定文件） | 專案資料夾，進 Git |
| `sets/<SET_ID>.json` | 專案資料夾，進 Git（純文字） |
| `scene.blend`、平面圖、渲染圖、定場照 | Git 外的輸出資料夾，文件只記路徑和 SHA-256 |

## 常見錯誤

- **家具浮在空中或插進桌面。** 放在家具上的東西，`base` 要等於下面那件的頂面高度，並寫 `"on"`，`plan_check.py` 會核對。
- **比例錯。** 門寬 0.8 到 0.9 m、高約 2.05 m；書桌高約 0.73 到 0.75 m；單人床長 2 m；天花板 2.4 到 2.7 m。
- **廣角往下拍，牆會歪。** 定場機位加 `"level": true`。
- **不同時段看起來一樣。** 每個時段都寫清楚開哪幾盞燈、陽光從哪個方向來。窗戶朝東的房間，傍晚曬不到太陽。
- **機位放不下。** 機位離牆或家具不到 0.3 m 會警告：實拍放不下，AI 也容易穿模。改用拆牆。
- **只看角落會高估可見度。** 書桌被椅子擋住中間時，角落還是看得到。`build_set.py` 在朝向鏡頭的每一面取 5×5 個點來算。

## 限制

- 家具有方塊、椅子、桌子、有門的殼體（`booth`）、薄貼地覆蓋（`floor_cover`，厚度最多 2 cm），另支援可辨識的環形燈腳架（`ring_light`）、開放書櫃（`bookcase`）與盆栽（`potted_plant`）。`yaw` 只能是 0、90、180、270。斜牆、多個房間和樓梯不支援，需要時在 Blender 裡手動加。新家具的曲面僅在原生白模保留，預演匯出仍為零件包圍盒，見 set-json 參考。
- 白模裡的替身是靜止的；會動的走位在 foyege 預演裡做，那邊的替身只會站。
- 腳本檢查的是能不能用，不是好不好看。風格和像不像這個人的房間要人看。
- 尺寸來自一般室內設計資料，不是台灣或日本的法規。角色比較矮時，眼睛高度和機位要跟著降低。
- 白模交給 AI 的方法來自廠商教學和一位作者的實測，在這台機器上還沒測過，見 [ai-handoff.md](references/ai-handoff.md)。
