# 白模交給 AI

白模畫面怎麼變成定場照和影片。這裡的方法大多來自廠商教學和一位作者的實測，在這台機器上還沒有用白模生成過，每一條都標了證據等級。

| 等級 | 意思 |
|---|---|
| 本專案實測 | 這個專案拍過、Owner 看過 |
| 他人實測 | 別人公開的測試，我讀過全文 |
| 廠商教學 | 賣這個服務的公司寫的，可能偏好自家工具 |

## 定場照：白模轉成實景

做法（廠商教學：fal.ai 的白模轉實景教學）：

1. **白模負責幾何。** 每個鏡頭的第一格就要出現所有關鍵物件，後面才不會冒出新東西。一個鏡頭只做一件攝影機的事。
2. **用改圖（image edit），不用從零生圖。** 第一張圖放白模畫面，提示詞寫明「第一張圖是幾何的唯一依據」，其他參考圖只管風格。
3. **參考圖裁成和輸出完全一樣的比例。** 比例不同時，模型會自己改構圖。
4. **先寫空間描述。** 例如「左邊是窗，窗下是書桌，鏡頭對著門」，讓模型知道每個方塊是什麼。
5. **風格段落逐字重複。** 同一個場景的每張圖都用一模一樣的風格文字，光和材質才會一致。
6. **疊圖自查。** 生成的圖和白模畫面以 50% 疊在一起看。教學用輪廓圖算分數，每個鏡頭生 20 到 40 張再挑。

在這裡：

- 疊圖用 `overlay_check.py`，它輸出 50% 疊圖、紅藍輪廓圖和 `layout_match` 分數。分數會被光線影響，同一個機位、同一個時段的候選互相比較，再看輪廓圖，不要單看分數。範例房間的實測：同樣的幾何 0.91 到 0.95（光線相近）或 0.65 到 0.77（白天比深夜）；位移 1% 到 2% 或放大 3% 是 0.52 到 0.59；另一個機位 0.49。教學用的輪廓 PSNR 在範例房間裡分不出對錯（全部在 24 到 28 dB），所以只列出來，不拿來判斷。
- 白模畫面用和生成相同的時段光：白天的定場照就疊白天的白模。
- 定場照沿用使用者已有的本機生圖／改圖工作流；選用外部 imagegen 時依該工具與上傳授權。這份教學不把外部服務設成必要依賴。

## 預演：在同一個房間裡排走位

`to_previs.py` 把 `set.json` 的一個機位轉成 `foyege-cinematic-direction` 技能裡 `scripts/build_previs.py` 的輸入（下面的相對路徑從本技能目錄執行，Codex／Claude 安裝皆相同）：牆、門板和家具零件都變成方塊（不放天花板，拆掉的牆也不放），替身放在標記位置，機位當成固定鏡頭。改輸出檔裡的 `keys` 排動作和運鏡，再跑 foyege 的預演腳本。

```bash
python scripts/to_previs.py --set SET.json --camera C1 --out previs_C1.json --frames 121 --fps 24 --res 1280x704
```

```bash
blender --background --factory-startup --python-exit-code 1 --python "../foyege-cinematic-direction/scripts/build_previs.py" -- --scene previs_C1.json --out OUT_PREVIS
```

範例房間實測（2026-11-07）：25 個方塊、1 個替身，預演跑 24 秒，出第 1、61、121 格和俯視圖。限制：foyege 的替身固定是站著、1.6 m 高，不會坐也不會趴；坐著或趴桌的替身會和椅子重疊，`to_previs.py` 會在輸出的 `source.notes` 寫出來。站在墊高地板上的替身（`base`）會照高度放上去。foyege 的機位也不支援 `level`，廣角往下拍時牆會歪。

## 影片：白模當參考

### 首尾圖（FL2VA）

本專案實測（T01，2026-11-06）：H3 用首尾圖，握手腕 4 支全成功；只給首圖，握的那一下 4 支都有問題。首圖和尾圖都可以從白模機位畫面做出來，人物和房間就會在同一個位置。代價是每個接觸鏡頭都要先做一張對的尾圖。

### 參考影片（Ref2VA）

他人實測（ai-muninn，Blender 白模加 H3 Ref2VA，RTX 5090）：

- 白模動畫放在參考影片欄，角色照片放在參考圖欄。提示詞寫明每個替身代表哪個角色，並且要求不要畫出替身。
- 替身只用膠囊和方塊，加一個不對稱的記號，看得出正面。
- 輸出的解析度和格數要和參考影片一樣，格數要在 17k+5 上（例如 124）。
- 守得住的：誰在左誰在右、誰擋住誰。守不住的：精確的距離和小角度的轉身。
- 全身遠景的臉會糊，中景就好了。
- 每支約 90 秒（14 步）。

歷史研究環境曾有 H3 Ref2VA 節點、int8 權重、ref2v LoRA 與 FunControl，當時未在該專案驗證。公開讀者需核對自己的實際檔案、節點與版本，依既有授權先做小測試，不能將此紀錄當成目前已安裝。

## 交給 AI 時要附的東西

每個用到這個場景的鏡頭卡，都附上：

- SET ID 和版本。
- 機位 id，以及那個機位、那個時段的白模畫面（路徑和 SHA-256）。
- 一段空間描述：從這個機位看出去，左、中、右各是什麼，窗在哪邊、光從哪裡來。
- 這個場景固定的風格段落，逐字貼上。
- 道具在這一鏡的狀態，例如毯子在椅背上還是在主人身上。

## 已知風險

- 白模太空，模型會自己補家具。要出現的東西都要在白模裡，至少放一個方塊。
- 生成的畫面常把房間變大。疊圖時先看門、窗和大件家具的位置。
- 人物比例要另外檢查。在 `set.json` 的 `actors` 放一個和角色同身高的替身，確認桌子和床的高度看起來對。
