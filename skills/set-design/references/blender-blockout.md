# Blender 白模

`build_set.py` 把 `set.json` 建成灰色白模，自動檢查，再出參考圖。白模只負責位置、比例、視線和光的方向，不做材質和人物。

## 指令

```bash
blender --background --factory-startup --python-exit-code 1 --python scripts/build_set.py -- --set SET.json --out OUT_BUILD
```

| 參數 | 預設 | 意思 |
|---|---|---|
| `--samples` | 24 | Cycles 取樣數，已開降噪 |
| `--res` | 960x540 | 機位畫面的尺寸，要和之後生成的畫面同比例 |
| `--times` | 全部 | 只算某幾個時段，例如 `--times day,night` |
| `--no-render` | 關 | 只建模、檢查和存檔，約 3 秒 |

預設用單張支援的 GPU，NVIDIA 優先 OptiX，其次 CUDA；可加 `--gpu-name "YOUR_GPU_NAME"` 選定實際卡片，`--backend` 可明確選後端。輸出資料夾必須還不存在。只有 Blender 軟體本身不支援任何配置的 GPU 後端時，未指定顯卡的自動模式才允許 CPU，manifest 會留下完整探測與理由；後端支援但硬體未出現、找不到指定顯卡、GPU 忙碌、OOM 或渲染失敗都停止，不退 CPU。先核對目標卡負載，不自行停止其他工作；只以已選裝置的負載決定排程，依技能入口的單卡規則；只啟用一張 GPU，CPU 不參與 Cycles 混合渲染。建模、射線與 PNG／平面圖檢查仍由 CPU 執行，因為這些程式沒有 GPU 實作。

## 建模規則

- 地板和天花板都蓋過牆厚。牆依門窗切成好幾段：窗戶下方和上方各一段，門上方一段。S、N 兩面牆的兩端延伸蓋住轉角，轉角不會漏光。
- 家具預設是方塊，物件名稱就是家具的 id。`shape: "chair"` 做成座面加椅背，`shape: "table"` 做成桌板加四隻腳，`shape: "booth"` 做成背板、兩側、頂板、墊高地板和一扇有窗的門，零件叫 `<id>__back`、`<id>__leg0`、`<id>__side0`、`<id>__door0` 等（`booth` 用 id 命名的是背板）。放在家具上的東西，底部高度等於下面那件的頂面。
- 人物替身是膠囊身體（物件名稱就是替身的 id）、球形的頭和鼻子方向的小方塊；坐姿另加大腿和小腿。替身只用來看比例和視線，不代表姿勢。
- 每件家具的正面貼一塊深色小板（`<id>__front`），從任何角度都看得出它朝哪裡。這也是 H3 參考影片教學建議的「不對稱記號」。
- 門板預設關著；`leaf: "open"` 開 90 度。立面圖會隱藏全部門板，門的開口才看得到。
- 窗戶只有開口，沒有玻璃，陽光可以直接照進來。
- 俯視圖上才會顯示家具 id 的文字，機位畫面裡不會出現。

## 輸出的圖

| 檔案 | 內容 | 光 |
|---|---|---|
| `plan_top.png` | 正上方的正交俯視圖，有 id 文字，拿掉天花板 | 均勻白光 |
| `elev_N.png` 等 | 站在房間裡看那面牆的正交立面圖；拿掉對面的牆、天花板，和離這面牆超過 1 m 的家具和替身 | 均勻白光 |
| `cam_<機位>_<時段>.png` | 每個機位在每個時段的畫面；有 `wild_wall` 的機位會拆掉那面牆和牆上的門 | 照 `times` 和 `lights` |

`elev_N` 是看北牆，畫面左邊是西。`elev_E` 是看東牆，畫面左邊是北。

## S02 白模的可讀性（2026-11-07）

- `booth.door: slide` 的停放終態改用實心門板，不再把窗框畫成朝鏡頭的洞；`closed` 和 `open` 的窗框保留。這仍是簡化終態，沒有驗證滑門機構或掃掠動作。
- 燈具代理家具可填 `light` 指向燈的 id，並填 `color_off`（RGB 0–1，預設 0.08 灰）。每個時段照該燈的 `times` 切換外殼明暗；沒有 `light` 的家具維持原行為。這是代理色，不是發光材質或成片驗收。
- 人工檢查用的語義標註圖和正常白模分開存；標註圖不可當材質或幾何參考送生成。

## 自動檢查

### 窗光落點

`build_set.py` 在任何拆牆或機位隱藏前，對有 `sun` 的每個時段、每扇窗的室內面四角（向窗洞內縮 1 mm），先沿向陽方向回推到牆外面再多 1 mm，才沿入射方向打原生網格射線，輸出 `sunlight.json`。完整牆厚都在光路上；先撞到窗楣、窗框或其他物件、尚未抵達室內窗洞時，記 `OCCLUDED_APERTURE`、首碰點和物件，`landing` 留空。通過窗洞後才記室內落點。每筆保留精確室內窗角、室內取樣點、牆外起點、入射向量、牆厚與首碰物件／面／座標。太陽在窗背面、地平線下或關閉時另記原因。`--no-render` 也執行，屬 CPU 幾何計算，不啟動 Cycles。

要查指定家具／替身是否照到直射光，可呼叫 `direct_sunlight_on_objects(scene, sun, targets)`：朝陽原生三角面各取四個重心樣本，沿向陽方向查遮擋。正樣本證明那一點受直射；零樣本僅代表取樣未見，不能宣稱整個物體絕對無光。表面取樣比例不是照度或全身面積比例。來源中的互斥替身會一起參與遮擋，需要各時段狀態時先派生輸入。

方位角從 +X 逆時針，高度角向上；報告與實際 Blender 太陽共用同一方向函式。四角只界定近似邊界，不能證明整片光斑無遮擋、玻璃／窗外障礙已模擬，或漫射天光與半影照度正確。寫「照到北牆」之前，必須先核對原生落點；不能用生成圖當幾何證據。

材質已定才填 `items[].color`，未定不填就是中性灰。不再依清單順序套彩色調色盤；既有 JSON 的顯式顏色仍保留，重新使用時需核對其依據，不自動把歷史綠色茶櫃當正式材質。

| 檢查 | 做法 | 過關 |
|---|---|---|
| `camera_clearance` | 從機位往六個方向打射線，找最近的物件 | 0.3 m 以上；不到是 WARN |
| `must_see` | 把目標和它的零件包成一個盒子，在盒子朝向鏡頭的每一面取 5×5 個點，先看點在不在畫面裡，再從機位打射線，看第一個打到的是不是目標本身或它的零件 | 看得到 40% 以上是 PASS；10% 到 40% 是 WARN；更少是 FAIL |

`must_see` 也可以填替身的 id，確認這個機位拍得到人；填門或窗的 id 時，改在門窗開口上取 5×5 個點，視線沒被擋住（或停在那扇門的門板上）就算看得到。

`must_see` 不只看角落。範例房間裡，椅子擋住書桌中間時，只看角落會算出 8/9 可見，用面上取樣是 40%。

## 範例房間的實測（2026-11-07）

- 這台機器、Blender 5.2.3、Cycles CPU、24 取樣、960×540：13 張圖 84 秒，每張 5.5 到 9 秒；加上坐著的替身、椅背和桌腳之後，渲染合計 89 秒。
- 故意放錯的版本（床擋門、椅子佔了衣櫃前方、書架擋窗、走道堵死、機位貼著書架、`must_see` 指到不存在的 id），兩支腳本都有抓到。
- 第一版的時段光有問題：白天天空亮度 0.3 太暗，傍晚和深夜都開吸頂燈，看起來一樣。改成白天天空 1.2 加曝光 0.8、傍晚只開吸頂燈、深夜只開檯燈之後，四個時段才分得出來。寫新場景時，先用 `--times` 只算一個機位確認亮度，再全部算。
- 20 mm 廣角往下拍，衣櫃的垂直線明顯傾斜；加 `"level": true` 之後就正了。

## 手動加東西

腳本做不到的（斜牆、圓桌、樓梯、窗簾），打開 `scene.blend` 手動加，但要記得：

- `set.json` 才是母本。手動加的東西寫進 `DESIGN_SETS` 的備註，重新跑腳本時會被蓋掉。
- 手動加的東西不在 `plan_check.py` 的檢查裡，要自己看。
- 存成新的版本號，不要覆蓋舊的 `.blend`。

## 這份腳本參考了誰

做法參考 foyege 技能的 `build_previs.py`（白模和正交俯視圖）、blender-orchestrator 的場景建構指南（先牆、再大件、再小件、燈、機位；物件高度要用一半高度定位；常見錯誤是浮空和比例錯），以及 fal.ai 的白模轉實景教學（視線射線檢查、機位離物件至少 0.5 m）。程式碼是自己寫的，沒有複製。來源見 [sources.md](sources.md)。
